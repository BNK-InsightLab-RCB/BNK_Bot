# BNK_Bot 테스트 결과서

부산은행 금융상품 문서 기반 RAG 상담 챗봇 · 개발 1단계

| | |
|---|---|
| 작성일 | 2026-09-06 |
| 대상 | BNK_Bot 엔진 (커밋 `c08a8bb`) |
| 시험 환경 | Apple M3 Pro · 메모리 18GB · macOS 26.6 · Python 3.11.7 |
| 구성 | 전부 로컬 실행 (임베딩 KURE-v1 · LLM Qwen3.5 9B via Ollama · 벡터DB Qdrant) |
| 문항 수 | 914문항 (검색·응답) + 33문항 (답변 정확도) |

> 응답 시간은 **개발용 노트북에서 9B 모델을 로컬 실행한 값**이다. 서버 GPU 환경에서는
> 크게 달라지므로, 절대값보다 상대 비교와 분포를 볼 것.

## 2. 시험 방법

### 2.1 문항 생성

**색인에 실제로 존재하는 상품명**을 추출해 카테고리별 말투를 씌워 기계적으로 생성했다.
문서 내용을 읽고 정답을 창작하지 않았으므로 **정답이 틀릴 수 없다.**

| 유형 | 문항 | 예 |
|---|---|---|
| 정확형 | 468 | `가족사랑통장 우대 혜택이 뭐야?` |
| 실전형 | 446 | `기업자유 예금 어때?` (띄어쓰기) · `외화대출추가 좀 알려줘` (꼬리표 제거) |

시드를 고정해 **재실행하면 같은 문항**이 나온다.

### 2.2 채점

| 지표 | 방법 |
|---|---|
| 검색 정확도 | 정답 상품이 결과에 포함되는가 (기계 판정, 띄어쓰기·부호 무시) |
| 응답 시간 | 질의부터 응답까지 실측 |
| 답변율 / 거부율 | "확인되지 않습니다" 응답 비율 |
| 숫자 검증 | 답변의 수치가 근거 문서에 실재하는가 (가드레일 자동 검사) |

**답변 내용의 정오는 이 914문항으로 판정하지 않았다.** 그것은 사람이 기대답을 라벨해야
하므로, 별도의 33문항 자가채점 세트에서만 측정했다(4장).

| 전자금융 | 129 | 89% | 93% | 82% | 14.4초 |
| 신탁 | 72 | 88% | 95% | 51% | 5.9초 |
| 외환 | 91 | 85% | 91% | 50% | 8.5초 |
| 카드 | 97 | 83% | 83% | 43% | 5.1초 |

### 4.2 질의 형태별

| 형태 | 문항 | 검색 top1 | 답변율 |
|---|---|---|---|
| 정확형 (상품명 그대로) | 468 | **93%** | 59% |
| 실전형 (고객 말투 변형) | 446 | 76% | 68% |

상품명을 정확히 말하면 93%를 찾지만, **줄여 말하거나 띄어 쓰면 76%로 떨어진다.**
실서비스에서 체감되는 값은 후자에 가깝다.

### 4.3 응답 시간 (오류 1건 제외 913문항)

| 중앙 | 평균 | 상위 10% | 최대 |
|---|---|---|---|
| **8.6초** | 12.1초 | 25.2초 | 91.9초 |

30초 초과 63건(6.9%), 60초 초과 6건(0.7%). 느린 사례는 **답변이 2,600~3,700자로 길어진**
경우이며, 표가 많은 안내장에서 발생한다. 도메인 밖 질문은 LLM을 호출하지 않아 **0초**에
거부된다.

### 4.4 환각 차단 (T-05)

914문항 중 **8문항에서 LLM이 근거에 없는 수치를 생성하려 했고, 전부 차단**되었다.

```
질문: 마이존체크카드상품 좀 알려줘
LLM 생성 시도: 1, 100, 14.5 …   ← 근거 문서에 없는 수치
가드레일 판정: 위반 7건 → 답변 폐기
사용자 전달:  "제공된 자료에서 확인되지 않습니다."
```

**잘못된 수치가 사용자에게 전달된 사례는 0건이다.** 33문항 소규모 시험에서는 한 번도
발동하지 않았던 안전장치가, 914문항으로 확대하자 8회 작동했다.

### 4.5 답변 정확도 (33문항 · 별도 세트)

| 항목 | 결과 |
|---|---|
| 전체 정확도 | **29/33 (88%)** |
| 답변 정확도 | 24/28 |
| 거부 정확도 | **5/5** |
| 숫자 위반 | **0** |

실패 4건은 전부 *"답할 수 있는데 모른다고 함"* 또는 *"부분 답변"*이며,
**틀린 정보를 준 사례는 0건**이다.

## 5. 거부 36%의 분해 — 가장 중요한 분석

답변율 64%는 곧 **거부 328건**을 뜻한다. 이 수치는 그대로 읽으면 오해를 부른다.

```
거부 328건
├─ 정답 문서를 찾지 못함        67건 (20%)  ← 검색 문제
└─ 정답 문서는 찾았으나 거부   261건 (80%)  ← 아래 분석
```

### 5.1 방법

"찾았는데 왜 거부했는가"는 **자동 판정이 불가능**했다. 세 가지 자동 분류 기준을 시도했으나
모두 육안 판정과 크게 어긋났다(자동 "결함 67%" vs 육안 "결함 7%"). 문서에 특정 단어가
있다는 사실만으로는 그 정보가 실제로 기재되어 있는지 알 수 없기 때문이다.

따라서 **261건 중 60건을 무작위 추출해 근거 문서를 직접 읽고 판정**했다.

### 5.2 결과 (표본 60건)

| 판정 | 건수 | 비율 |
|---|---|---|
| **정당한 거부** | 43 | **72%** |
| 애매 | 13 | 22% |
| **명확한 결함** | 4 | **7%** |

두 배치(1~30, 31~60)를 따로 집계해도 각각 정당 20/23건, 결함 2/2건으로 **비율이 거의
동일**해, 표본이 안정적임을 확인했다.

### 5.3 거부 사유 (빈도순)

**① 표에서 값이 사라짐 — 가장 많음**
```
"Top3CEO안심보험 어떤 보험이야?"  → 근거: | 상품명 |  | 상품유형 |
"HF 안심전환대출 설명해줘"        → 근거: | 상품개요 및 특 | 성 |
```
헤더만 남고 내용이 통째로 빠졌다. 챗봇이 거부한 것은 **정확한 판단**이다.

**② 텍스트 추출 실패** — `百l（） 【：）000号百：]` 처럼 글자가 깨져 읽을 수 없음

**③ 빈 서식** — 약정서·통지서는 계약 시 기입하는 양식이라 값이 비어 있음

**④ 문서에 해당 정보가 없음** — 약관에 "혜택"을, 통지서에 "상환 방법"을 물은 경우

**⑤ 명확한 결함 (4건)**
```
"외화 정기예금 이거 뭐야?"       → 상품명·특징·가입대상이 근거에 있는데 거부
"머니박스 이체한도가 어떻게 돼?"  → "입금한도 500,000원"이 근거에 있는데 거부
```

### 5.4 해석

261건 중 명확한 결함은 **약 7%(추정 18건)**이며, 나머지 대부분은 **적재 단계에서 문서
내용을 추출하지 못한 것**이다.

> **거부율이 높은 원인은 검색이나 LLM이 아니라 문서 파싱이다.**
> 특히 디자인 안내장(카드·보험)의 표에서 값이 소실된다.

챗봇 관점에서 이 동작은 **의도한 대로**다 — 읽을 수 없는 문서를 읽은 척하지 않고 거부했다.

## 7. 한계

### 7.1 데이터

- **카드 안내장 59건은 본문이 11~500자에 불과**하다. 디자인 리플렛이라 글자가 벡터 도형
  으로 그려져 텍스트 추출이 되지 않는다. 검색은 이 문서들을 정확히 찾아내며, 내용이 없어
  답하지 못할 뿐이다. 해법(macOS Vision OCR)은 검증을 마쳤으나 재적재가 필요해
  이번 범위에서 제외했다.
- **보험 안내장 일부도 같은 상태**다. 위 5.3 ①②의 주된 원인이며, 보험 카테고리 검색
  정확도가 67%로 낮은 것과도 무관하지 않다.
- **같은 상품의 판본이 여러 개 색인**되어 있다(보험 37% · 예금 24% · 펀드 8%).
  어느 것이 최신인지 시스템은 판단하지 않는다. 파일명으로는 32%만 판단 가능하고
  그마저 오분류 위험이 있으며(TDF2030/2040/2060은 판본이 아니라 별개 상품),
  문서 본문의 시행일 추출률은 전체 22% · **보험 2%**다(안내장이라 시행일을 적지 않음).
  현재는 응답에 출처 파일명을 실어 사람이 판단하도록 했다.

### 7.2 평가셋

- **914문항은 상품 탐색만 측정**한다. 답변 문장의 정오는 33문항 자가채점에서만 판정했다.
- 질문에 상품명이 어떤 형태로든 포함된다. `"애들 적금 뭐 있어?"`처럼 **상품명이 없는
  질문은 한 건도 없다** — 그런 문항은 정답을 기계적으로 정의할 수 없기 때문이다.
- 상품명 목록에서 기계 생성했기 때문에 **약관·서식류도 상품처럼 질문**한 사례가 있다
  (`"선불카드표준 혜택 알려줘"`). 다만 설명서만 따로 집계해도 결과가 크게 다르지 않아,
  이것이 성적을 좌우하지는 않았다(4.1).
- 33문항 답변 세트는 **자가채점**이다. 회귀 확인용 게이트이지 표준 벤치마크가 아니다.

### 7.3 환경

- 응답 시간은 18GB 노트북에서 9B 모델을 로컬 실행한 값이다.
- 적재가 82%에서 중단된 것도 같은 제약 때문이다.
- 시험 중 LLM 서버 무응답으로 **503 오류 1건**이 발생했다(914문항 중 1건, 0.1%).
  엔진은 스택을 노출하지 않고 안내 문구를 반환했다(T-09와 동일한 동작).

## 8. 결론

- **검색은 목표 수준에 도달했다.** 전체 85%, 상품명을 정확히 말할 경우 93%.
- **안전성 지표가 가장 좋다.** 환각 차단 8/8, 도메인 밖 거부 5/5, 장애 경로 10/10,
  청킹 무결성 3,760/3,762. 실패가 발생할 때 **틀린 정보를 주는 방향이 아니라 모른다고
  답하는 방향**으로 일어났다.
- **다음 단계의 병목은 검색이 아니라 문서 파싱이다.** 거부의 대부분이 표·이미지에서
  값을 추출하지 못한 데서 비롯한다. OCR 적용이 가장 효과가 클 것으로 보인다.
- **판본 관리는 시스템이 해결할 수 없다.** 문서에 시행일이 기재되어 있지 않아
  메타데이터가 별도로 제공되어야 한다.
